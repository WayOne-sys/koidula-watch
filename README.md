# Koidula Queue Watch

Монитор, который сообщает в Telegram через **@KoidulaQueueWatchBot**, когда в GoSwift (estonianborder.eu / eestipiir.ee) появляются **свободные для бронирования слоты на 20.12.2026**. Параметры: пункт пропуска **Koidula**, категория **B** (легковой автомобиль), направление Эстония → Россия, тип очереди «Reserve for certain time».

Монитор **ничего не бронирует** и **не запрашивает данные водителя или автомобиля**. Бронирование вы делаете сами по ссылке из уведомления.

---

## 1. Что выяснено о GoSwift (проверено 29.10.2026)

| Вопрос | Ответ |
|---|---|
| Официальный API | **Нет.** Документированного или публичного API у GoSwift нет. |
| robots.txt | Отсутствует (HTTP 404). |
| Условия использования | Явного запрета на автоматический доступ нет. Есть п. 1.6: аккаунт могут заблокировать за действия, «наносящие ущерб работе системы GoSwift». Монитор работает без аккаунта и держит нагрузку минимальной. |
| CAPTCHA / логин на шагах 1–4 | Нет. |
| Лимиты частоты | Не опубликованы; заголовков rate-limit в ответах нет. |
| Где видна доступность конкретной даты | Шаг 4 публичного мастера бронирования. |

**Как монитор получает данные.** Он повторяет действия браузера на шагах 1–4 мастера. Шаги 5–6 с данными водителя и автомобиля монитор не открывает.

1. `POST /yphis/preReserveSelectWaitingArea.action`, где `placeInQueue.vehicleInQueue.vehicleCategory.name=B`.
2. `POST /yphis/preReserveSelectQueueType.action`, где `placeInQueue.borderCrossingPoint.id=2`. Значения: Narva = 1, **Koidula = 2**, Luhamaa = 3.
3. `POST /yphis/preReserveSelectQueueType.action`, где `queueType=1` («Reserve for certain time») и `action:preReserveSelectTimeslot=Next`.
4. `GET /yphis/findOpenTimeslot.action?preferredDate=20.12.2026` возвращает HTML-сетку на 4 дня (20–23.12) по 24 часовых слота.

Шаги 1–3 выполняются один раз на сессию. Дальше каждая проверка — **один GET размером около 1,3 КБ**. Если сессия истекла, она переоткрывается автоматически.

**Как распознаётся состояние слота.** Используется класс элемента `div.slotContainer[data-time="20.12.2026 HH:MM"]`:

| Разметка | Значение | Действие монитора |
|---|---|---|
| `slotFree` | слот можно забронировать | 🟢 уведомление |
| `slotLocked` + «Full» | бронирование открыто, мест нет | 🟡 одно информационное сообщение (не «есть места»), затем проверки продолжаются |
| `slotLocked` + «Not available» | бронирование ещё не открыто | молча продолжает проверять |
| другой класс | вёрстка изменилась | ⚠️ предупреждение «проверьте вручную» |

На 29.10.2026 все 24 слота 20.12.2026 имеют состояние «Not available».

### Ограничения

- **Это не официальный интерфейс.** Если GoSwift изменит мастер или вёрстку, монитор пришлёт сообщение об ошибке или о «непонятном состоянии». Ложного сообщения «есть места» в этом случае не будет.
- **Класс `slotFree` подтверждён по скрипту страницы, но живьём не наблюдался.** Скрипт выбирает слоты селектором `.slotContainer.slotFree`, а 29.10.2026 свободных слотов не было ни в одной дате. Текст внутри свободного слота неизвестен. Поэтому решение принимается по классу, а не по тексту.
- **Учитывается только 20.12.2026.** Свободные слоты 21–23.12, которые приходят в том же ответе, игнорируются. Если сайт вернёт сетку без 20.12, это считается ошибкой, а не «мест нет». Обе ситуации покрыты тестами.
- **Время открытия неизвестно точно.** По объявлению на сайте новые слоты категории B выпускаются **1-го числа каждого месяца**, количество ограничено, разбирают их быстро. Час не указан. Поэтому по умолчанию заданы два усиленных окна: ночь 31.10 23:30 – 01.11 03:00 и утро 01.11 07:00–10:00, оба с интервалом 30 с.
- **Koidula с 24.02.2026 закрыт для пересечения с 19:00 до 07:00.** Брони на ночные часы действуют, но вызов на границу происходит с 07:00. Если свободен ночной слот, монитор добавляет об этом напоминание.
- **Уведомление не гарантирует бронь.** Между уведомлением и вашим входом на сайт слот могут занять.
- **Путь Python-клиента не проверен на живом сайте.** Последовательность запросов воспроизведена и проверена в браузере, но песочница разработки не имеет доступа к estonianborder.eu. Перед запуском по расписанию выполните `check-once` (см. раздел 3).

## 2. Как устроено

```
koidula_watch/
  config.py     переменные окружения, расписание, жёсткий минимум интервала 20 с
  goswift.py    клиент мастера (шаги 1–4) и парсер сетки
  monitor.py    цикл, усиленные окна, дедупликация, ошибки, heartbeat
  notifier.py   Telegram Bot API
  state.py      state.json (переживает перезапуск) и журнал checks.jsonl
  fixtures.py   генератор HTML в формате сайта (для тестов и simulate)
```

- **Расписание** (Europe/Tallinn): с 31.10.2026 22:00 до 20.12.2026 19:00 проверка каждые 60 с ±10 %, в усиленных окнах каждые 30 с. Монитор просыпается точно к началу окна. Интервал ниже 20 с задать нельзя.
- **Дедупликация.** О слоте, который остаётся свободным, повторно не сообщается. Если слот исчез и появился снова, уведомление придёт не чаще раза в `REPEAT_COOLDOWN_MINUTES`. Состояние хранится в `data/state.json`, поэтому повторов нет и после перезапуска. Если Telegram не принял сообщение, оно будет отправлено на следующей проверке.
- **Ошибки.** После 5 неудачных проверок подряд приходит 🔴, повтор не чаще раза в 30 мин. После восстановления приходит ✅. Пауза между проверками при ошибках растёт экспоненциально до 15 мин. HTTP 429/503 и `Retry-After` учитываются.
- **Журнал.** `data/checks.jsonl` — одна строка на проверку со статусом, счётчиками и свободными часами. `data/monitor.log` — подробный лог с ротацией по 5 МБ.
- **Служебные сообщения.** ▶️ при запуске, 💓 каждый день в 09:00, ⏹ по окончании.

## 3. Локальная проверка (до развёртывания)

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env            # заполните TELEGRAM_BOT_TOKEN
set -a; . ./.env; set +a

python -m pytest -q             # 28 тестов: парсер, клиент, дедупликация, расписание
```

**Telegram chat_id.** Напишите боту `/start` в Telegram, затем выполните:

```bash
python -m koidula_watch get-chat-id     # выведет TELEGRAM_CHAT_ID=... → в .env
```

**Тестовый режим: доставка без реальных мест.**

```bash
python -m koidula_watch test-telegram          # одно сообщение «[ТЕСТ] проверка доставки»
python -m koidula_watch simulate free          # 🟢 «есть места», затем повтор подавлен дедупликацией
python -m koidula_watch simulate full          # 🟡 «открыт, но мест нет»
python -m koidula_watch simulate other_day_free  # свободен 21.12, а не 20.12 → «есть места» НЕ приходит
python -m koidula_watch simulate error         # 🔴 ошибка, затем ✅ восстановление
python -m koidula_watch simulate free --dry    # то же, но только вывод в консоль
```

Все сообщения из `simulate` начинаются с «🧪 [ТЕСТ, данные смоделированы]». Сайт при этом не запрашивается, а боевой `state.json` не изменяется.

**Одна реальная проверка сайта.** Выводит все 24 слота 20.12.2026:

```bash
python -m koidula_watch check-once            # без Telegram
python -m koidula_watch check-once --notify   # и отправить результат в Telegram
```

Ожидаемый результат до 1 ноября — `Статус: not_open`, 24 × `not_open «Not available»`. Если команда завершилась ошибкой `SessionInitError` или `GridMissingError`, сайт изменился или недоступен с вашего IP. В таком случае не запускайте расписание, пока не разберётесь.

**Запуск без ожидания старта** (для проверки цикла): `python -m koidula_watch run --now`.

## 4. Развёртывание на Oracle Cloud Always Free

### 4.1. Создать виртуальную машину

1. Зарегистрируйтесь на <https://www.oracle.com/cloud/free/>. Домашний регион выбирается один раз, Always Free-ресурсы создаются только в нём. Для Эстонии ближе всего **EU Frankfurt** или **EU Stockholm**.
2. Откройте **Compute → Instances → Create instance**.
   - **Image:** Canonical Ubuntu 24.04.
   - **Shape:** `VM.Standard.A1.Flex` (Ampere ARM, 1 OCPU, 6 ГБ) или `VM.Standard.E2.1.Micro` (AMD). Обе формы входят в Always Free, и монитору хватит любой. Если A1 отвечает «Out of capacity», возьмите E2.1.Micro или повторите позже.
   - **Networking:** VCN по умолчанию, публичный IPv4.
   - **SSH keys:** загрузите свой публичный ключ.
3. Входящие порты открывать не нужно: монитор делает только исходящие HTTPS-запросы. Оставьте открытым только SSH (22).

### 4.2. Установить Docker

```bash
ssh ubuntu@<PUBLIC_IP>
sudo apt-get update && sudo apt-get install -y ca-certificates curl git
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker ubuntu && exit     # перелогиньтесь, чтобы группа применилась
ssh ubuntu@<PUBLIC_IP>
docker run --rm hello-world
```

### 4.3. Загрузить проект и настроить

```bash
# с вашего компьютера:
scp -r koidula-watch ubuntu@<PUBLIC_IP>:~/

# на сервере:
cd ~/koidula-watch
cp .env.example .env && nano .env          # TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID
chmod 600 .env
mkdir -p data && sudo chown 10001:10001 data   # контейнер работает от непривилегированного uid 10001
```

### 4.4. Проверить и запустить

```bash
docker compose build
docker compose run --rm koidula-watch test-telegram     # должно прийти «[ТЕСТ] …»
docker compose run --rm koidula-watch simulate free     # 🟢 с пометкой ТЕСТ
docker compose run --rm koidula-watch check-once        # реальная проверка с этого сервера
docker compose up -d                                    # боевой режим
```

После `up -d` придёт ▶️ «Монитор запущен». До 31.10 22:00 монитор ждёт, затем начинает проверки. Часовой пояс задан внутри приложения (`TZ_NAME=Europe/Tallinn`) и не зависит от часового пояса сервера, который у Oracle обычно UTC.

### 4.5. Наблюдение

```bash
docker compose ps                         # STATUS: healthy
docker compose logs -f --tail 50          # лог в реальном времени
tail -n 5 data/checks.jsonl               # последние проверки
cat data/state.json                       # состояние дедупликации и ошибок
docker compose restart                    # перезапуск: состояние сохраняется
docker compose down                       # остановить
```

Перезапуск после ребута VM обеспечивает `restart: unless-stopped`. Docker-сервис после установки через get.docker.com включён в автозагрузку.

### 4.6. Важно: Oracle может остановить «простаивающую» VM

По документации Oracle, Always Free-инстанс считается простаивающим и может быть остановлен, если за 7 дней 95-й перцентиль загрузки CPU ниже 20 %. Для A1 также учитываются сеть и память ниже 20 %. Монитор почти не нагружает машину, а мониторинг длится около 7 недель, так что риск реальный. Что можно сделать:

- **Перевести аккаунт в Pay As You Go.** Always Free-ресурсы при этом остаются бесплатными, а Oracle указывает, что конвертация аккаунта защищает от остановки простаивающих инстансов. Понадобится карта. Поставьте бюджет-алерт на 1 €.
- **Следить за ежедневным 💓.** Если оно не пришло в 09:00, проверьте VM в консоли Oracle: Instances → Start.
- Скрипты, имитирующие нагрузку, я не рекомендую: это обход политики провайдера.

## 5. Параметры (.env)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | — | обязательны, хранятся только в `.env` |
| `TARGET_DATE` | `2026-12-20` | целевая дата |
| `BORDER_POINT` / `VEHICLE_CATEGORY` | `koidula` / `B` | пункт пропуска и категория |
| `MONITOR_START` / `MONITOR_STOP` | `2026-10-31T22:00` / `2026-12-20T19:00` | период, Europe/Tallinn |
| `CHECK_INTERVAL_SECONDS` | `60` | обычный интервал |
| `INTENSIVE_WINDOWS` | ночь и утро 1.11 по 30 с | `START/END@SEC,…` |
| `MIN_INTERVAL_SECONDS` | `20` | ниже 20 не опускается |
| `NOTIFY_OPENED_FULL` | `true` | сообщить «открыт, но мест нет» |
| `REPEAT_COOLDOWN_MINUTES` | `15` | антиспам для «мигающих» слотов |
| `ERROR_ALERT_THRESHOLD` / `ERROR_ALERT_REPEAT_MINUTES` | `5` / `30` | алерты ошибок |
| `HEARTBEAT_HOUR` | `9` | ежедневное «я жив» (`off` — выключить) |

После изменения `.env` выполните `docker compose up -d`. Контейнер пересоздастся, состояние сохранится.

## 6. Ответственное использование

- Монитор делает по умолчанию 1 запрос в минуту (≈1,3 КБ) и 2 в минуту в усиленных окнах, представляется честным `User-Agent` и уважает 429/503/`Retry-After`.
- Он не обходит CAPTCHA, авторизацию или ограничения. Если GoSwift добавит что-либо из этого, монитор перестанет получать сетку и сообщит об ошибке. Обходить такие меры не нужно.
- Если GoSwift попросит прекратить автоматические запросы или опубликует правила, выполните `docker compose down`. Вопросы можно задать по адресу info@eestipiir.ee.
